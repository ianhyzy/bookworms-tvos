# Sources, shelf choices, and iCloud

See [tvOS views](../VIEWS.md) for shelf options and [tvOS data sources](../DATASOURCES.md) for providers, merge rules, sync schedules, and limits.

CWA redirects and catalog paging stay within the configured HTTPS origin. The app uses HTTP Basic authentication with credentials from Keychain. See [storage and performance](STORAGE_AND_PERFORMANCE.md) for cache behavior.

## iCloud

**Settings → General → iCloud storage** enables private CloudKit storage. It is off by default; users turn it on. The `LibraryArchive` record type is deployed to the production schema. The archive contains source snapshots, which include the reader's own Hardcover reviews as plain text, and saved AI design records. Credentials are excluded. Covers and downloadable fonts stay in local caches. The cloud archive uses a file asset so it can exceed the local preferences budget.

Each successful Hardcover fetch saves the authenticated account ID with its complete source snapshot, and the library reads only the newest snapshot for the active account. The shelf still limits displayed books, but the cloud snapshot retains the full fetched library. A device with no active Hardcover account, such as a newly restored Apple TV, shows the newest Hardcover snapshot in the archive until a credential is added or the cloud worklist names an account that the archive contains.

The archive also spares Hardcover requests. When an automatic check at launch or activation finds a source due, the Apple TV reads the archive first and waits up to 10 seconds for it. It then checks each source's daily gate again, so a snapshot of the active account that another device saved within the last day ends the check without a provider request. Only the sources still due are fetched. A read that takes longer keeps running in the background. **Sync now** fetches without reading first. A fetch keeps each book's cover URLs from the account's newest snapshot; see [combining and deduplicating data](../DATASOURCES.md#combining-and-deduplicating-data).

A separate `SpineWorklistV1` record holds the active account ID, the snapshot's sync date, and all of that account's book IDs for the iPhone and Mac companions. After each archive save, the Apple TV publishes the worklist from the snapshot in that archive, so the two sync dates match. The TV publishes a nonempty list only while the Hardcover source is enabled with a connected, unexpired credential whose authenticated account matches the snapshot. A TV with an expired session or no credential publishes nothing and leaves the existing record unchanged, so a restored shelf cannot reactivate a worklist that another device cleared. Disabling or disconnecting Hardcover publishes an empty list after the archive sync. A companion reads book metadata from the matching account snapshot in `library-v1`; it does not receive a Hardcover credential from the Apple TV. The worklist uses a fixed record name, `spine-worklist-v1`, and a JSON `payload` data field.

Each companion writes one `SpineDesignV1` record per book. The record name depends only on the account and book, so the latest save from any companion replaces the previous design, and the Apple TV accepts designs from any generator. Its JSON `payload` contains bounded colors and typography choices, including an optional Google Fonts family, PostScript name, and instance weight, account and book IDs, a metadata hash, a cover-content hash, a generator version, and an optional one-line `provenance` of at most 80 characters. The provenance names the model tier that made the design: no model token for Private Cloud Compute, `model:<provider>/<model>` for the reader's backup model, `model:apple/on-device`, or `model:local` for local defaults. The iPhone and Mac read the tier from that model token and, for a design without one, from its generator: `ios-pcc-v2` is Private Cloud Compute, `mac-foundation-models-v2` is Apple's on-device model, and any other generator is local defaults. A companion redesigns a book whose design came from a lower tier than its current run's, unless the reader recolored it; see [companion designs](BOOK_WALL.md#companion-designs). The Apple TV validates designs for every book in the active Hardcover snapshot in bounded CloudKit batches and keeps them in a separate local cache. It reads that cache on launch even when CloudKit is unavailable, prunes entries that no longer match the active books, and schedules a cache clear when Hardcover is disabled or disconnected. Book Wall draws spines from these designs; see [companion designs](BOOK_WALL.md#companion-designs).

The iPhone companion saves a reader's cover choice as a `CoverChoiceV1` record named `cover-choice-v1-` plus the SHA-256 of `accountID:bookID`. Its JSON `payload` holds the account and book IDs, an HTTPS cover URL, an optional Hardcover edition ID, and the choice date. Choosing the default cover deletes the record. The Apple TV reads cover choices with the designs, in the same bounded batches and at the same times, and keeps them in `Caches/Bookworms/cover-choices-v1.json`. It accepts only HTTPS URLs on public host names without credentials, ports, or fragments. A valid choice becomes the displayed book's first cover; the default covers remain fallbacks. Source snapshots and the companion work-item hash keep the default covers, so designs still match. The old API-key designs remain stored but generation stays disabled.

The iPhone and Mac companion saves a reader's series choice for a book as a `SeriesLinkV1` record named `series-link-v1-` plus the SHA-256 of `accountID:bookID`. Its JSON `payload` holds the account and book IDs, an optional `linkedSeriesID`, the `standsAlone` and `ownLook` flags, and the choice date. Choosing the default deletes the record. The Apple TV reads links after the designs and cover choices, at the same times, accepts only a link for a book in the active Hardcover snapshot, and keeps them in `Caches/Bookworms/series-links-v1.json`. It never writes a link.

A `SeriesLookV1` record holds the look that one group of series books shares on every device; see [series designs](BOOK_WALL.md#series-designs). Its record name is `series-look-v1-` plus the SHA-256 of `accountID:seriesID:group`, where the group is the Discworld group or nothing, then `|` and the first author's folded name, such as `City Watch|terrypratchett`. Its JSON `payload` holds the account and series IDs, the group, the source book ID, an origin, the creation date, an optional edit date, an optional `provenance` that holds only the model token of the design the look was made from, and the colors and type fields of a design. Looks saved before `provenance` existed decode without it. The Apple TV checks them with the design's rules (`SpineDesignV1.isValidLook`) and, as the iPhone does, requires an account ID of at most 512 characters, a positive series ID, a group of at most 200 characters, a non-blank, one-line origin of at most 80 characters, and, when present, a one-line provenance of 1 to 80 characters. Looks the Apple TV samples from covers (origin `tvos-local-v1`) record no provenance. The iPhone and Mac read a look's tier from its `provenance`, else from its `origin` as a design's generator, so `tvos-local-v1` looks count as local defaults. The first look saved decides its group among looks from the same model tier; a companion may replace a look from a lower tier that the reader never edited, and the Apple TV draws the replacement after its next read. A look that any device copies from a design whose colors the reader chose has an edit date equal to its creation date, so no upgrade replaces those colors. After reading links, it reads the looks of the active snapshot's look groups in the same bounded batches and keeps them in `Caches/Bookworms/series-looks-v1.json`.

A device saves a missing look with a create-only save: a new record saved with `.ifServerRecordUnchanged`, which CloudKit rejects when the record exists. On that rejection the device fetches the saved look and keeps it, so the first look saved decides the group. The Apple TV never replaces or deletes a saved look.

Cloud sync merges sources by identity and sync date, and legacy designs by book ID and generation date. A newer snapshot without series, which an older build writes, keeps the replaced snapshot's series. Conditional saves retry concurrent updates instead of overwriting another device's newer data. A worklist for an older snapshot cannot replace a newer worklist for the same account; an equal-date update can clear the list when the source is disabled. Unchanged archives and unchanged worklists are not uploaded again. A source sync queues a cloud update, and paid designs are saved to iCloud before relying on cloud storage beyond the local preferences budget. Each automatic check reads the archive once: before a due fetch when a source with a saved credential is due, or after the check otherwise. The read also retries an upload that failed. A fetched snapshot then queues its own upload, which reads the archive again before it saves. When the archive holds a newer copy that is still more than a day old, the shelf shows that copy and then the fetched one.

The companion design cache is separate from the retained API-key design store. Small legacy design collections retain a durable local preferences copy. Larger collections can exceed that budget after a successful cloud save, with a local disk copy for fast access. If iCloud is unavailable, existing local data stays usable. Account changes stop cloud syncing until the user enables storage for the new account. Turning the setting off does not delete cloud records.

The current implementation transfers one archive asset when the archive changes. The entire asset is transferred when any archived data changes. The worklist, per-book designs, cover choices, series links, and series looks are separate records. CloudKit development and production environments are separate: deploy `SpineWorklistV1`, `SpineDesignV1`, `CoverChoiceV1`, `SeriesLinkV1`, and `SeriesLookV1` with their `payload` data fields to production before uploading a candidate that uses them.

## Verification

Unit tests cover OPDS parsing and invalid feeds, credential-origin restrictions, stable source IDs, account-specific snapshots, merging, shelf selection and ordering, per-source daily scheduling, the archive read before a due fetch and its 10-second limit, cloud merges, persistent design recovery, worklist publication, design validation, series link and look record names and validation, create-only look saves, reads that report a failed batch or record as incomplete, and cache recovery. UI tests cover Shelf, Sources, and Storage settings. Follow the [device testing procedure](TESTING.md) to verify live services and production CloudKit.
