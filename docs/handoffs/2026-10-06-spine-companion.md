# Spine companion handoff

The Bookworms iPhone and Mac companion designs book spines from Hardcover covers and shares them with the Apple TV app through private CloudKit. Book Wall draws them. The work spans two active repositories. This handoff describes the tvOS integration on `main`.

## Where things are

| Piece | Location | State |
| --- | --- | --- |
| iPhone and Mac companion | `~/Developer/BookwormsApps/ios`, private GitHub repository `ianhyzy/bookworms-ios` | One target builds both the iPhone and Mac apps. It designs spines with the best model tier the device has: Private Cloud Compute, then the reader's backup model from another provider, then Apple's on-device model, then local defaults without a model. Every tier writes generator `ios-pcc-v2`. Its designs add the optional `fontFamily`, `fontPostScriptName`, `instanceWeight`, and `provenance` fields, and `provenance` names the tier. |
| tvOS integration | `~/Developer/BookwormsApps/tvos`, private GitHub repository `ianhyzy/bookworms-tvos` | `SpineCloudStore`, worklist publication, design, cover-choice, series-link, and series-look fetch and caches, series-look creation, [Book Wall companion designs](../BOOK_WALL.md#companion-designs) and [series looks](../BOOK_WALL.md#series-links-and-looks) behind `BookPresentation.showsCompanionSpines`, the model credits in **Settings → Spines**, and companion cover choices in every view behind `showsCompanionCovers`. |
| Retired Mac app (**Bookworms Spines**) | `~/Developer/BookwormsApps/macos`, archived repository `ianhyzy/bookworms-macos` | Make no changes there. The Apple TV still accepts its existing `mac-foundation-models-v1` and `mac-foundation-models-v2` designs as ordinary valid designs. |

## How the companion works

1. The Apple TV syncs the full Hardcover library and, with iCloud storage on, saves it to the `library-v1` archive in the private database of `iCloud.gay.ian.Bookworms`. The archive holds the full fetched library, not the displayed limit.
2. After that archive save, the TV publishes a `SpineWorklistV1` record (record name `spine-worklist-v1`, JSON in a `payload` data field) from the snapshot in the uploaded archive, not from memory, so the companion's sync-date match holds. It holds the active Hardcover account ID, the snapshot's sync date, and every book ID, sorted and deduplicated. A snapshot installed during the sync sets the pending flag, so the next loop iteration uploads it and republishes, even after a failed publish.
3. The TV publishes a nonempty list only while the Hardcover source is enabled with a connected, unexpired credential whose authenticated account matches the snapshot. It gates on local state (`hardcoverConnected`, `hardcoverEnabled`, `!hardcoverSessionExpired`, and the uploaded snapshot's account) and makes no Hardcover request before publishing. A connected credential's authenticated validate or fetch sets `activeHardcoverAccountID`; a credential-free restore can adopt the account the cloud worklist names, but that TV never lists work. A TV with an expired session or no credential publishes nothing and leaves the record unchanged. Disabling or disconnecting Hardcover publishes an empty list.
4. The companion subscribes to worklist changes. It reads book metadata from the matching account snapshot in `library-v1`, downloads each cover over HTTPS, and designs it; see the iOS app's README for the steps. It writes one `SpineDesignV1` record per book: background, foreground, and accent colors (`#RRGGBB`), a typeface (`serif`, `sans`, `rounded`, or `monospaced`), a weight (400–700), an uppercase flag, a work-item hash of the book metadata, a cover-content hash, a generator version, and, when one fits, a Google Fonts family and instance.
5. The TV validates designs in bounded batches (matching account, book, and work-item hash; foreground contrast at least 4.5:1; optional font fields bounded as on the iPhone) and caches them in `Caches/Bookworms/spine-designs-v1.json`, separate from the retained API-key design store. It reads designs at launch, on activation, and after each cloud sync, then publishes them to Book Wall, which downloads each design's Google Fonts face during preparation.
6. The TV shows the latest valid design for each book, whichever app or tier made it. The TV has no model of its own (Foundation Models is unavailable on tvOS), so the companions are its models. Each companion run picks the best tier available on that device when it starts: Private Cloud Compute, unless the reader chose the backup model instead on that device; else the reader's backup model (Anthropic, OpenAI, Google, or a custom endpoint); else Apple's on-device model; else local defaults from the cover palette, the measured title, and the book's Hardcover genres. A run that reaches Private Cloud Compute's daily limit waits for the reset instead of falling to a lower tier. A design's `provenance` records its tier: no model token for Private Cloud Compute, `model:<provider>/<model>`, `model:apple/on-device`, or `model:local`. The iPhone and Mac read a design's tier from that model token (the iOS app's `SpineDesignV1.modelToken`) and, without one, from its generator: any `ios-pcc-` version is Private Cloud Compute, a Mac design (any `mac-foundation-models-` version) is Apple's on-device model, and any other generator is local defaults. The iPhone keeps a design from Private Cloud Compute or a backup model, or whose tier is at least its run's, from any generator, and keeps a design whose colors or font the reader chose (`hasReaderEdits`) until the reader chooses another cover. It redesigns a design from Apple's on-device model or local defaults when its run's tier is better, unless the reader chose its colors or font, a design that stands in its system typeface for a font that couldn't download (a `font:system` token) once a run at its tier gets the font, any design after the reader chooses another cover, and a design from its own tier or a lower one when the reader asks for a redesign. A kept design whose book's metadata or cover image changed is saved again under the new hashes when its face letters the book's title and author.
7. Each book carries every Hardcover series it belongs to (`seriesMemberships`) in `library-v1`. The TV reads the companion's `SeriesLinkV1` records with the designs, then the `SeriesLookV1` records of the snapshot's look groups. It creates a missing look with a create-only save, from a group member's usable companion design, copied as stored, or, for a group of two or more books without one and after a complete cover-choice read, from Book Wall's cover-sampled look (origin `tvos-local-v1`). A look copied from a design keeps only the design's model token and `font:system` token as its `provenance`, and one copied from a design whose colors or font the reader chose (a `generated-colors:` or `reader-font` token, `hasReaderEdits`) has an `editedAt` equal to its creation date; a `tvos-local-v1` look records none. The iPhone adds `reader-font` to a look's `provenance` when the reader chooses the look's font. The companions read a look's tier from its `provenance`, else from its `origin` as a design's generator (the iOS app's `SeriesLookV1.tier`), so a `tvos-local-v1` look counts as local defaults, the lowest tier. Among looks of one tier, whichever device saves a group's look first decides it. A companion run upgrades a look that the reader never edited (`editedAt` absent, no `reader-font` token) from a new design of the look's source book, or of the group's best-ranked member for a `tvos-local-v1` look: from a better tier when Apple's on-device model or local defaults made the look, or from its own tier when the look awaits its font and the new design doesn't. A redesign the reader asks for on the whole series remakes the group's look from any tier and marks it edited. Both keep the look's group and creation date and record the remake in `remadeAt`. The TV never remakes a look. Book Wall draws the look on every member whose link doesn't keep its own look and whose title and author the look's loaded face can letter; see [series links and looks](../BOOK_WALL.md#series-links-and-looks).

The JSON contract lives in `ios/Bookworms/Models/CloudContract.swift` and `Bookworms/Services/SpineCloudStore.swift`. Keep them compatible; both pin the same digests.

## Contract comparison

Both sides encode `Date` with the default `JSONEncoder` strategy (seconds since 2001 as a number). Record types `SpineWorklistV1`, `SpineDesignV1`, `CoverChoiceV1`, `SeriesLinkV1`, and `SeriesLookV1`, the `payload` data field, the container ID, the worklist record name, the design record name (`spine-design-v1-` + SHA-256 of `accountID:bookID`), the cover-choice and series-link record names (`cover-choice-v1-` and `series-link-v1-` + SHA-256 of `accountID:bookID`), the series-look record name (`series-look-v1-` + SHA-256 of `accountID:seriesID:group`, where the group is the Discworld group or nothing, `|`, and the folded first author, such as `City Watch|terrypratchett`), the optional `provenance` on designs and series looks (one line of 1 to 80 characters), the create-only series-look save on the TV, and the work-item hash (SHA-256 of account ID, book ID, title, author, detail cover URL, cover URL, joined by newlines) are identical, and both test suites pin the same digests. The contrast formula is the same WCAG relative-luminance ratio. The TV checks the optional font fields as the iPhone does. The table lists where the validators differ.

| Item | tvOS | iPhone | Effect |
| --- | --- | --- | --- |
| `SpineWorklistV1.accountID` length | No bound | At most 512 characters | None in practice; Hardcover IDs are short. |
| Worklist payload size | No bound | At most 5 MB | None in practice. |
| `coverHash` format | 64 hex digits, either case | 64 lowercase hex digits | None; the iPhone writes lowercase. The TV is looser. |
| `workItemHash` format | Must equal the TV's own lowercase SHA-256 | 64 lowercase hex digits | The TV check is stricter and binds the design to the book. After a metadata edit, the TV shows the local spine and the iPhone keeps showing the old design until the iPhone's next generation run saves the design again under the new hash, or a redesign from a better tier. A design whose face can't letter the new title or author keeps its old hash, so the TV keeps showing the local spine. |
| Color hex case | `#` + 6 uppercase hex digits | Same | None; the iPhone emits uppercase. |
| `generatorVersion` | Any non-blank string | Any non-blank string; gives a design without a model token its tier | None on the TV, which shows designs from any generator. |
| `provenance` model tier | Not read; any valid value | Read as the design's or look's tier, with no model token on an `ios-pcc-` record counting as Private Cloud Compute | None on the TV, which draws designs and looks from any tier. |
| Archive size the iPhone reads | No bound on the TV | At most 50 MB | A very large archive stops the iPhone; the TV does not warn. |
| Extra `Book` fields | Encoded in `library-v1` | Ignored unless `CloudBook` declares them, such as `seriesName` and `seriesMemberships` | None. |

## Remaining steps

1. **Signed end-to-end check**: a signed iPhone or Mac and the Apple TV on one iCloud account. Confirm the worklist lists every book, a companion design reaches the TV cache with its font fields, and Book Wall shows it while other views show covers. See [testing](../TESTING.md).
2. **Privacy policy**: the [policy text](../RELEASING.md#apple-tv-privacy-policy-text) names the Google Fonts requests that Book Wall makes. Publish the same wording and effective date in the web policy before uploading a candidate with `showsCompanionSpines` on.
3. **Deploy `SpineWorklistV1`, `SpineDesignV1`, `CoverChoiceV1`, `SeriesLinkV1`, and `SeriesLookV1`** (each with a `payload` Bytes field) to the production CloudKit schema before any TestFlight build uses them. See [releasing](../RELEASING.md).
4. **Design refresh cadence**: the TV refetches every design, cover-choice, series-link, and series-look record on launch, activation, and after each cloud sync. A new design or series look for a current-year book rebuilds Book Wall, even while it is on screen. Consider subscriptions with silent push, as the iPhone uses for the worklist.
5. **Validator alignment**: decide whether the TV should adopt the iPhone's lowercase-only `coverHash` and the account ID length bound.
6. **Live Hardcover check**: confirm that Hardcover accepts the library query's `compilation`, `books_count`, and `primary_books_count` fields. A rejected field fails the whole library query.

## Constraints

- Follow each repository's `AGENTS.md`. The companion stays read-only toward Hardcover and has no tvOS view dependency.
- Keep one active Hardcover account. A worklist or design for another account must never mix into the active shelf.
- A worklist for an older snapshot must not replace a newer one for the same account.
- Unsigned builds prove compilation only, not iCloud access or push delivery.

## Open questions for the owner

- Disabling or disconnecting Hardcover on one Apple TV publishes an empty worklist, which pauses the companion for every TV on the iCloud account until another TV's next cloud sync republishes. Should a local disable clear the shared worklist?
- After a relaunch, a revoked credential can publish one nonempty worklist before the first failed refresh marks the session expired. The account is still the last authenticated one. Is that acceptable?
